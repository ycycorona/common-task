# 文档规范（本仓库适配版）

来源：`y-agent-toolkit/agent-playbook` 的 `documentation/documentation-conventions.md`，同步记录见
[`SYNC.md`](SYNC.md)。意图与判定来自 playbook；角色划分、路径与例外是本仓库的真实内容。
SPEC、tracker、orchestration 相关规则不适用于本仓库（见 SYNC.md 的 Dropped）。

## 文档角色

| 角色 | 位置 | 什么时候写 |
| --- | --- | --- |
| 操作/部署记录 | `docs/<主题>.md` | 本机做过一次、以后可能重做的事，记现状与做法 |
| 研究/逆向分析 | `docs/<主题>.md` | 对第三方产品的取证结论，带分析方式与日期 |
| 归档（一次性证据） | `archives/<主题>.md` | 一次性抓取/调研的链路与产物特征，绑定当日数据 |
| 用法说明 | 脚本头部注释、根 `README.md` | 单文件脚本的用法优先写在这里，不另建文档 |
| 设计文档 | `devps/docs/design-v*.md` | 有分支/协议/信号路径的实现前设计 |

没有任何角色的文档不新建：先用上面最近的一类，或写进脚本头部注释。

## 元数据（按角色最小必填）

每篇文档开头给到足够说明它是什么、边界在哪，不套统一表头：

- 操作记录：标题、日期、环境（机器/路径）、适用范围。
- 研究/分析：标题、被分析对象与版本、分析方式、分析日期。
- 归档：标题、数据核对日期、一次性边界（哪些字段会变、哪些结构稳定）。
- 设计文档：版本、状态、适用边界。

`Last Validated: YYYY-MM-DD`（可选 ≤40 字说明）只回答"上次确认这篇还成立是什么时候"，最新一行覆盖旧的；
不写提交号、测试数、变更历史——那些属于 Git。只修错别字/链接/格式、没有复核内容时，不改这一行。
尚未复核过的写 `Not yet validated`。

## 不把契约藏在普通文档里

"唯一依据""完成标准""接口约定"这类契约不放普通文档：设计文档（`devps/docs/design-v*.md`）承担，
并写明版本与状态。归档与操作记录只描述事实与做法，不声明验收条件。

契约一旦被实现追着改，先停下问用户，不要改文档去迎合代码。

## 决策落文档，不只留在聊天里

做过取舍的地方（为什么选这个方案、翻掉过什么结论）写进对应文档的一节：设计文档、操作记录或归档都行。
翻掉的结论保留原文并加一行说明，不删了重写。

## 一次证据绑定一次版本

日期、环境、样本版本都写进正文；新的核对产生新日期或新文档，不覆盖旧结论。接口路径、字段名这类
会漂移的东西标出核对日期，别写成常青结论。

## 既有文档的过渡

已存在的文档保持路径与内容，不批量重写：下次因别的原因触碰时，顺手补上缺失的元数据；
发现已经过期的结论，加一行说明而不是改写历史。

## 检查

文档改动：链接与路径可达、`git diff --check`，再通读一遍确认没有把测量结论写成约定。
