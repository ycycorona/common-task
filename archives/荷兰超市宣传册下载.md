# 荷兰超市宣传册（reclamefolder）下载与产物说明

记录 AH、Jumbo、Vomar、LIDL、ALDI 五家当期优惠宣传册的抓取链路、选期陷阱与产物特征。
配套脚本：[`fetch_supermarket_folders.py`](fetch_supermarket_folders.py)。

数据核对于 2026-10-02（第 40 周）。各家的接口路径与字段名可能变动，链路结构相对稳定。

---

## 1. 结论速览

| 超市 | 官方源 | 取法 | 本周有效期 |
|---|---|---|---|
| AH | 无 PDF，仅分页图片 | 聚合站图片 → ImageMagick 合成 | 9/28 – 10/4 (wk 40) |
| Jumbo | Publitas 附件 PDF | 页面 widget id → Publitas | 9/30 – 10/6 (wk 40) |
| Vomar | Publitas 附件 PDF | iframe → Publitas | wk 40 |
| LIDL | leaflets.schwarz PDF | JSON API 直出 `pdfUrl` | 9/28 – 10/4 (wk 40) |
| ALDI | ipaper PDF | Next.js 数据 → `GetPDF.ashx` | 9/28 – 10/4 (wk 40) |

五家里**只有 AH 需要自行合成 PDF**，其余四家都有官方 PDF 直链。

## 2. 各家抓取链路

### 2.1 AH —— 最麻烦的一家

AH 官网（`www.ah.nl/bonus/folder`）有 Akamai 防护，直连一律 `403 Access Denied`，
换 UA、加完整浏览器头、加 `Sec-Fetch-*` 都无效。官方也不提供 PDF，只有分页图片。

因此改走聚合站 **Folder24（Prisero 后端）**，它镜像了同一套每周页面：

1. 列表页 `https://folder24.nl/fb/23854449356420276/albert-heijn`
   内含 `/folder/<n>` 形式的周报页链接（`n` 为序号）。
2. 每个 `/folder/<n>` 页面的 `<title>` 形如
   `ALBERT HEIJN folder - Van maandag 28 september 2026`，据此得到**生效起始日**。
3. 该页面内嵌 Prisero 图片包 hash（64 位十六进制），页面图片为
   `https://priserocdn.com/m2/nl/<hash>/<n>.jpg`，**页码从 0 开始**，
   请求到不存在的页返回 `403`（用这一点探测末页）。
4. 逐页下载后用 ImageMagick 合成 PDF。

图片为 1250×2585 px，单页约 300–450 KB。

### 2.2 Jumbo

`https://www.jumbo.com/folder` 是 Nuxt SPA，HTML 里看不到 PDF，但能看到挂载点：

```html
<div id="jumbo-actiefolder-rtek-40" class="fep-publitas" data-testid="fep-publitas"></div>
```

这个 `id` 就是 Publitas 的出版物名。组件源码（`/_nuxt/B2rvqwtL.js`）里写死了组织名：

```js
o = `https://view.publitas.com/jumbo-supermarkten/${s.folderName}`
```

所以出版物地址为 `https://view.publitas.com/jumbo-supermarkten/<folderName>`，
页面内含附件 PDF 直链（`/pdfs/<uuid>.pdf?response-content-disposition=attachment...`）。

### 2.3 Vomar

`https://www.vomar.nl/folder` 是 Nuxt SSR，直接可读：

```html
<iframe src="https://view.publitas.com/folder-deze-week?publitas_embed=maximized"></iframe>
```

`folder-deze-week` 是**固定短链**，会 302 到当期出版物
（如 `/folder-deze-week/weekendfolder-week-40-ed6jror4ja79/`），同样从中取附件 PDF。
另有 `/folder-volgende-week` 指向下周。

### 2.4 LIDL

先取总览页 `https://www.lidl.nl/c/service-contact-folders/s10008124`，
其中的 `/l/folders/<slug>` 链接即各分册标识符（如 `hah-wk40-2026`）。

再用官方 JSON API 取元数据：

```
https://endpoints.leaflets.schwarz/v4/flyer?flyer_identifier=<slug>&region_id=0
```

返回的 `flyer.pdfUrl` 即 PDF 直链（`https://assets.leaflets.schwarz/leaflets/pdfs/<uuid>/<name>.pdf`），
`fileSize` 给出字节数。分册类型靠 slug 区分：`hah-wkNN-YYYY` 是主周报，
`-nf-` 是 Non-Food，`-weekenddeals-` 是周末特辑。

### 2.5 ALDI

`https://www.aldi.nl/folders` 是 Next.js，数据在 `__NEXT_DATA__` 里：

```
props.pageProps.page.leaflets["0"].tiles → tiles1 { title: "Folder van deze week",
                                                     reference.path: "/folders/folder-van-deze-week" }
```

注意 tiles 是**对象**且含 `@name`/`@path` 等元数据键，遍历时要跳过 `@` 开头的键。

进入 `https://www.aldi.nl/folders/folder-van-deze-week` 后得到 ipaper 播放器地址
`https://folder.aldi.nl/fixed/2026/<slug>/`，在末尾追加 `GetPDF.ashx` 即得 PDF
（本期 146 MB，64 页）。

## 3. 两个选期陷阱

这两处都会**静默下到错误的册子**——文件名正常、PDF 有效，内容却不是本周的。脚本已针对性处理。

### 3.1 AH：发布日 ≠ 生效周

聚合站列表里的日期是**发布日期**。2026-10-02 当天，列表最新条目是
`folder-albert-heijn-folder-oktober-2026-2026-10-02-...`，按日期选会下到一份
**Disneyland 促销插页（7 页）**，而不是本周的 Bonus 宣传册（45 页）——两者同日发布。

正解是按页面标题里的**生效起始日**选：

```
/folder/1  Van maandag 21 september 2026
/folder/2  Van maandag 28 september 2026   ← 本周（10-02 时选它）
/folder/3  Van maandag 5 oktober 2026      ← 下周，尚未生效
```

规则：取**起始日 ≤ 今天**中最新的一个。这样既跳过同日发布的插页，也不会提前取下周一才生效的那期。

### 3.2 LIDL：会提前几天上线下周的册子

LIDL 的 `startDate`/`endDate` 是**发布窗口**，`offerStartDate`/`offerEndDate` 才是**优惠生效期**：

| slug | 发布窗口 | 优惠生效期 |
|---|---|---|
| `hah-wk40-2026` | 9/24 – 10/4 | **9/28 – 10/4** |
| `hah-wk41-2026` | 10/1 – 10/11 | 10/5 – 10/11 |

10-02 时 wk41 已能访问，用发布窗口判断会把它当成本周。必须用 `offerStartDate` 判断。

## 4. 产物特征

以 2026-10-02 那批为例（`folders/2026-10-02/`）：

| 文件 | 页数 | 体积 | 页面尺寸 | 文字层 |
|---|---|---|---|---|
| `AH-bonusfolder-2026-09-28.pdf` | 45 | 18 MB | 1250×2585 pt | **无** |
| `ALDI-Folder-week-40-magnolia.pdf` | 64 | 147 MB | 595×1012 pt | 有 |
| `Jumbo-jumbo-actiefolder-rtek-40.pdf` | 36 | 182 MB | 1080×1920 pt | 有 |
| `LIDL-Folder-Week-40-28-09-04-10-2026-09-28.pdf` | 51 | 66 MB | 468×794 pt | 有 |
| `Vomar-folder-deze-week.pdf` | 45 | 42 MB | 411×842 pt | 有 |

（体积按 1 MB = 10⁶ 字节，与脚本运行时打印的口径一致。）

需要注意的几点：

- **AH 无文字层**，纯图片。Spotlight 索引不到内容，也不能复制文字。原因是它由图片合成；
  其余四家的官方 PDF 都带文字层（Jumbo 约 7 千词、LIDL 约 6 千词可提取），可直接搜索/复制。
- **页面尺寸差异很大**，是各家原始排版不同所致，不是清晰度差异。ALDI/Jumbo 的内嵌图
  单张可达 2000 万像素以上，放大后细节充足。
- **体积主要来自原始图片质量**，Jumbo 182 MB、ALDI 147 MB 属于正常，不是下载损坏。
- 命名规则：`<超市>-<册子名>-<生效起始日>.pdf`，同一天重复下载会覆盖同名文件。

## 5. 使用建议

- **想搜商品/价格**：优先用 LIDL、Jumbo、ALDI、Vomar 四家（有文字层，`Cmd+F` 或 Spotlight 可搜）。
  AH 那份只能靠翻页或另做 OCR。
- **要 OCR AH**：本机 `tesseract` 已装，但只有 `eng`/`osd`/`snum` 语言包，**缺荷兰语**。
  需先 `brew install tesseract-lang` 再用 `-l nld`，否则识别荷兰语商品名会明显不准。
- **体积敏感**：Jumbo/ALDI 两份就占 300 MB 以上。压缩需注意本机 **未安装 Ghostscript**，
  而 ImageMagick 读取 PDF 依赖它（`magick` 会报 `gs: command not found` 并失败）。
  要压缩需先 `brew install ghostscript`，再执行：

  ```bash
  magick -density 100 in.pdf -quality 80 out.pdf
  ```

  未装 Ghostscript 时，可用的替代办法只有重跑脚本时少下几家、或换用能直接处理 PDF 的
  工具（如 `qpdf`、Python 的 `pypdf`，均需自行安装）。`sips` 不可用于此场景——它只转换首页。
- 产物目录 `folders/` 已在 `.gitignore` 中，不会进版本库。

## 6. 复现与排查

```bash
python3 archives/fetch_supermarket_folders.py              # 五家 → folders/<今天日期>/
python3 archives/fetch_supermarket_folders.py --only AH LIDL
python3 archives/fetch_supermarket_folders.py --outdir /tmp/folders
python3 archives/fetch_supermarket_folders.py --selfcheck  # 离线解析自检，不联网
```

依赖：`curl`（下载，带重试与断点续传）、ImageMagick（**仅 AH 需要**）。

链路失效时的排查顺序：

1. `--selfcheck` 先确认解析逻辑本身没坏（纯离线，不涉及网络）。
2. 单独跑一家（`--only <STORE>`）看具体报错。
3. 按 §2 的表格逐段核对：**列表页 → 详情页 → 文件直链**，定位是哪一段变了。
4. 常见失效点：Publitas 改版导致附件链接结构变化；LIDL API 版本号（现为 `v4`）升级；
   ALDI 的 `__NEXT_DATA__` 结构或 tile 标题文案变化；AH 聚合站改版或换图片 CDN。

日志里出现 `curl: (56) ... error: 403` 是**正常现象**——那是 AH 探测末页时预期的终止信号，
只要后续打印了页数并写出文件即成功。
